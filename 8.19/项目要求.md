# C语言数据结构项目要求（Ubuntu 20.04）

## 通用规范

### 编译环境

    gcc -Wall -Wextra -g *.c -o project
    valgrind --leak-check=full ./project

### 错误码定义（common.h）

    #define EINVAL  22   // 参数无效
    #define ENOMEM  12   // 内存分配失败
    #define ENOENT   2   // 记录不存在
    #define EEXIST  17   // 记录已存在
    #define EFULL   28   // 容量已满
    #define EAGAIN  11   // 资源暂时不可用

### 编码规范

* 所有 `typedef` 类型别名以 `_t` 为后缀
* 函数返回值：成功返回 `0`，失败返回负错误码
* 输出参数放在参数列表最后
* 输入参数使用 `const` 修饰
* 函数命名采用 `模块_操作` 前缀（如 `seq_insert`）
* 头文件组织：`common.h` 只放公共错误码等通用定义

## 项目一：学生成绩管理系统

### 1. 需求描述

开发一个命令行学生成绩管理系统，所有数据存储在内存中（无文件操作）。系统需支持：

* **学生信息管理**：学号（唯一）、姓名、5门课成绩、平均分（自动计算）
* **顺序表存储**：使用动态数组，初始容量10，满载自动扩容（*2）
* **补考名单**：当某学生有挂科（任意一门<60）时，删除该生记录时自动将其学号移入补考链表（链表存储）；撤销删除时，需同步将该学号从补考链表移除
* **撤销功能**：支持撤销最近20步操作（添加、删除、修改），撤销后恢复数据；栈满（undo_is_full 返回真）时新操作不再入栈并返回 EFULL
* **查找与排序**：按学号二分查找（主存储始终按学号升序）；按平均分降序排序仅用于显示（对副本排序，不改动主存储）

### 2. 功能菜单

    1. 添加学生（输入学号、姓名、5门成绩，自动计算平均分）
    2. 删除学生（输入学号，删除后自动加入补考名单）
    3. 修改学生信息（输入学号，修改姓名或成绩，重新计算平均分）
    4. 查找学生（按学号，显示完整信息）
    5. 显示所有学生（按平均分降序排列，基于副本排序，不改动主存储）
    6. 显示补考名单（仅学号列表）
    7. 撤销上一步操作（撤销添加/删除/修改，最多20步）
    8. 退出

### 3. 数据结构设计

    } op_type_t;

        int index;           // 操作在顺序表中的位置

## 项目二：图书借阅管理系统

### 1. 需求描述

开发一个命令行图书借阅管理系统，支持：

* **图书管理**：书号（唯一）、书名、作者、库存，使用**链表**存储（按书号升序）
* **读者管理**：读者ID（唯一）、当前借阅书号列表（最多10本，不可重复借同一本），使用**顺序表**存储
* **预约排队**：当图书库存为0时，读者可预约，预约者按**FIFO队列**等待
* **借书**：库存>0则借出（库存-1，记录读者借阅），库存=0则自动加入预约队列
* **还书**：库存+1，自动检查预约队列，找到预约该书（book_id 匹配）且入队最早的第一位预约者，按 FIFO 分配（库存-1，记录借阅，移除该预约）；若无人预约该书则库存保留
* **热门图书**：统计每本书被借阅次数（需在借书时累加），显示借阅次数最多的前10本

### 2. 功能菜单

    1. 添加图书（书号、书名、作者、库存量）
    2. 删除图书（按书号，删除前需在业务层检查该书是否存在借阅或预约，存在则禁止删除）
    3. 查找图书（按书号，显示详情）
    4. 显示所有图书（书号、书名、作者、库存）
    5. 注册读者（读者ID）
    6. 借书（输入读者ID和书号，库存充足则借出，否则加入预约队列）
    7. 还书（输入读者ID和书号，归还后自动分配预约）
    8. 查看预约队列（显示某本书的预约列表）
    9. 显示热门图书TOP10（按借阅次数降序）
    10. 退出

## 项目三：**员工考勤管理系统**

### 1. 需求描述

开发一个命令行员工考勤管理系统，支持：

* **员工管理**：工号（唯一）、姓名、部门、本月出勤天数，使用**链表**存储
* **打卡功能**：员工每天上班、下班各打卡一次，传入打卡类型和时间（小时、分钟），自动判断：
  * **上班打卡**（type=1）：时间在 9:00 及之前 → 正常；9:00 之后 → **迟到**，记录迟到分钟数（当前时间 - 9:00）。出勤天数 +1（迟到仍算出勤）
  * **下班打卡**（type=2）：时间在 17:00 及之后 → 正常；17:00 之前 → **早退**，记录早退分钟数（17:00 - 当前时间）
* **迟到早退记录**：使用**栈**存储最近50条违规记录（工号、日期、类型、分钟数）；栈满（violation_is_full 返回真）时新记录不入栈并返回 EFULL
* **请假审批**：员工提交请假申请（工号、开始日期、天数）入**队列**（FIFO），管理员从队首取出审批（批准/驳回）
* **统计**：计算各部门平均出勤率（假设每月22个工作日）

### 2. 功能菜单

    1. 添加员工（工号、姓名、部门）
    2. 删除员工（按工号）
    3. 查找员工（按工号）
    4. 显示所有员工
    5. 打卡（输入工号、打卡类型(1上班/2下班)、日期、小时、分钟，自动判断迟到/早退）
    6. 查看迟到早退记录（显示最近所有违规记录）
    7. 申请请假（工号、开始日期、天数）
    8. 审批请假（显示待审批列表，选择批准或驳回）
    9. 统计部门出勤率（输入部门名，输出平均出勤率）
    10. 退出

## 项目四：食堂窗口排队模拟器

### 1. 需求描述

开发一个食堂排队模拟器，模拟顾客点餐、排队、备餐、取餐过程，支持：

* **菜单管理**：菜品编号（唯一）、名称、价格、备餐时间（秒），使用**顺序表**（固定30个菜品）
* **顾客点餐**：输入菜品ID列表（最多5个），自动计算总备餐时间，生成排队序号，入**队列**（FIFO）
* **备餐台**：容量为10，使用**顺序表（定长数组）**存储正在备餐的订单（每个订单包含序号、剩余时间、菜品数），支持按序号任意移除已完成订单
* **时间模拟**：每秒执行一步：
  1. 备餐台中所有订单剩余时间减1
  2. 剩余时间为0的订单从备餐台移除（表示备餐完成，顾客取餐）
  3. 若备餐台未满且排队队列非空，从队首取出一个顾客加入备餐台开始备餐（剩余时间=总备餐时间）
* **状态查看**：实时查看排队队列、备餐台占用情况

### 2. 功能菜单

    1. 添加菜品（编号、名称、价格、备餐时间）
    2. 显示菜单
    3. 顾客点餐（输入菜品编号列表，自动入队）
    4. 查看排队队列（显示序号和总备餐时间）
    5. 查看备餐台（显示正在备餐的订单及剩余时间）
    6. 模拟一步（执行1秒）
    7. 自动模拟（输入步数，连续执行）
    8. 退出

## 项目五：超市收银排队系统

### 1. 需求描述

开发一个超市收银排队系统，模拟顾客购物、结账过程，支持：

* **商品管理**：商品编号（唯一）、名称、单价，使用**链表**存储
* **购物车**：每个顾客一个购物车，使用**栈**存储（商品编号、数量），同种商品多次加入时累加数量
* **结账入队**：顾客购物完成后，将购物车**按值复制**（生成副本）入**队列**（FIFO），并自动生成顾客ID
* **收银处理**：从队首取出顾客，遍历购物车栈计算总价，显示购物清单
* **查看状态**：可查看当前购物车内容、收银队列排队情况

### 2. 功能菜单

    1. 添加商品（编号、名称、单价）
    2. 删除商品（按编号）
    3. 显示所有商品
    4. 模拟顾客购物（先显示商品列表，让用户输入商品编号和数量，多次加入购物车）
    5. 查看当前购物车（显示商品名、数量、小计）
    6. 结账入队（将当前购物车复制入队，清空购物车）
    7. 收银处理（队首出队，计算总价并打印清单）
    8. 查看收银队列（显示队列中每位顾客的ID及购物车商品数）
    9. 退出

### 3. 数据结构设计

    /* ---------- 商品链表 ---------- */

    typedef struct {
        goods_node_t *head;

    } goods_list_t;
    
    /* ---------- 购物车栈（容量20） ---------- */
    typedef struct {
        int goods_id;
        int quantity;
    } cart_item_t;
    
    typedef struct {
        cart_item_t items[20];
        int top;
    } cart_stack_t;
    
    /* ---------- 收银队列 ---------- */
    typedef struct customer_node {
        int customer_id;
        cart_stack_t cart;     // 购物车副本（按值复制）
        float total_price;
        struct customer_node *next;
    } customer_node_t;
    
    typedef struct {
        customer_node_t *front;
        customer_node_t *rear;
        int count;
        int id_counter;
    } checkout_queue_t;

## 开发建议

1.**先实现底层数据结构**（顺序表、链表、栈、队列），再实现业务逻辑。

2.**每个接口先写测试用例**（在 `main` 中简单测试），再实现功能。

3.**完成后用 Valgrind 检测内存泄漏**：`valgrind --leak-check=full ./project`。

4.**代码风格**：函数长度不超过50行，变量命名使用 `snake_case`。
